# SAA学習プロジェクトの作業ルール

- 日本語で回答する。
- 教材の保管先は `docs/CONTENT_LIBRARY.md`、制作進捗は `docs/CONTENT_PROGRESS.md` を確認する。教材・公開範囲・分類を変更した後は `pnpm progress:update` と `pnpm progress:check` を実行して進捗表を更新する。原稿保管・内容確認・公開・ゲーム利用を区別し、保存先とGitHub同期の有無を報告する。
- 教材の収集・新規作成・内容改訂では、最初に `docs/CONTENT_CLASSIFICATION_GUIDE.md` を読み、用語・概念・システム・役・ビルド・ケースを分類する。`knowledge/game-classifications.json` に分類理由、タグ、元教材/単位の参照、出典、ゲーム利用案、保留事項を記録する。単純な誤字修正は分類の新設不要。教材の完成報告には分類IDと監査/取り込み状態を含める。
- ゲーム用タグを既存 `knowledge/units.json` へ無断追加せず、上記台帳で管理する。分類済み・内容監査済み・ゲーム実装済み・本人理解済みを区別する。
- 教材拡充の前に `knowledge/README.md`、`knowledge/INVENTORY.md`、`knowledge/EXPANSION_PLAN.md` を確認する。正本は `knowledge/units.json` と `relations.json`。変更後は `pnpm knowledge:export` と `pnpm knowledge:check`。教材の監査状態と本人の理解度を混同しない。
- 原計画と最新の状態は `docs/PROJECT.md`、`docs/TASKS.md`、`docs/CHECKPOINT.md` を確認する。

## 利用上限に備えた中断・報告

ユーザーは、利用上限の際に作業を中断し、完了した範囲の成果物と進捗・利用手順を報告することを希望している。

- 作業開始時、タスク区切り、サブエージェント追加前に、利用可能なら利用上限確認ツールで残量を確認する。モデルを使った頻繁な定期監視は追加しない。
- 取得できる適用対象の枠のいずれかが使用率90%以上になった場合、または利用不可・上限到達を示す場合は、新規タスク・追加委任を止める。90%は報告の余裕を残すための本プロジェクトの運用基準であり、製品の保証ではない。
- サブエージェントから上限エラーを受けた場合も追加委任を止める。親が使える場合は、保存済みの作業を確認し、提出可能な状態の整理と報告を優先する。停止したエージェントへ繰り返し再試行しない。
- タスク区切りごとに成果物を保存し、台帳とチェックポイントに、完了・未完了・未検証、実行した検証、次の着手点、成果物の場所を記録する。大きな教材やコードは、途中でも構文が成立する小単位で保存する。
- 上限前に中断できたときは、その時点の進捗、利用できる成果物、利用手順、残作業を日本語で報告する。
- 突然の上限到達ではモデルが応答できず、その瞬間の報告もできない場合がある。毎回必ず即時報告できるとは約束しない。再開できた最初の機会に、最後の保存状態を確認して未報告分を報告する。
- 利用枠の回復だけで自動再開する設定は現時点でない。再開指示または明示的に承認された予約に従う。過去の7:00停止・報告指示は履歴として扱い、現在のユーザー指示と `docs/CHECKPOINT.md` の目標に従う。
- 利用情報の欠落は残量ゼロや無制限と解釈しない。表示される週間枠だけでは別モデル・別機能の上限を断定しない。

- 公開教材を更新したら `docs/GAME_CONTENT_UPDATE.md` の連携ルールに従う。公開termsと単一選択questionsはテスト/ビルドでゲームへ自動変換される。独立したHTML教材は確認した内容をknowledge/game-supplement.jsonへ構造化し、分類・出典・進捗も更新する。生成済みpublic/tower/learning-catalog.jsonを直接編集しない。

- ゲーム全体の用語方針：ゲームの学習対象として登場する名称は教材に登場する用語を採用する。「更新お願いします」等は最新の公開教材・カード候補を確認して実装へ反映する依頼として扱う。教材にない創作名を学習用語へ混ぜない。カード名はknowledge/game-supplement.jsonのcardTermsで公開用語IDへ結び、生成時に照合する。

- 用語更新の固定対象は主人公3種（SE・SRE・クラウドアーキテクト）とデバフ5種（炎上・過負荷・遅延・枯渇・設定不備）。それ以外のカード（戦闘限定を含む）・敵・レリック（主人公固有を含む）・役の名称と学習補足は教材由来へ更新してよい。名称対応はgame-supplement.jsonのcardTerms/vocabularyで管理し、性能や保存IDとは分離する。

- ユーザー補足：更新作業の依頼は既存の公式公開サイト（GitHub Pages）への反映と公開確認までを含む。ローカル保存だけで更新完了としない。回答には実際に反映を確認した公開URLをリンクとして添える。公開に失敗した場合は未反映であることと原因を明記し、公開成功を主張しない。
