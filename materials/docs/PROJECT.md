# SAAへの道 — 実装仕様

更新日: 2026-10-05。原計画はルートの `SAAへの道.md`。対象はAWS初学者、1日20〜30分、日本語、iPhoneの縦画面。

現時点の提出版は2章・20問に限定。以下の全体仕様のうち、模試・ゲームは完成していない。確認済み範囲は `STARTER_REVIEW.md`、残作業は `TASKS.md` を参照する。旧作業の停止指示は履歴。現在はリポジトリ上で再開し、2026-10-06 07:00 JSTまでのiPhone向け試作ゲームが追加目標。試作の仕様は `GAME_PROTOTYPE.md`、最新の実績は `CHECKPOINT.md` を参照する。

## 成果物と順序

1. A: 試験範囲・教材形式・動作仕様を確定。
2. B: 2章20問で読む→解く→振り返る→保存する流れを成立させる。
3. C: 全12章、通常200問、模試65問×2、用語・復習・検索を完成。
4. G: 教材監査後にAWS構成カードゲームを制作。

教材はオリジナルであり、AWS公式認定教材でも本試験問題でもない。正答率は本試験のスケールドスコアへ変換しない。公式技術資料を参照し、出典と確認日を各教材・問題に保持する。

## 画面とデータ

今日の学習→テキスト（章→レッスン）／問題集（通常・復習・模試）／用語集／設定。冒険は教材監査後に追加。本文、図、全問題と解説をビルドに同梱し、外部CDN、フォント、AI、ログインに依存しない。

`src/types.ts` が共通データ契約。Chapter/Lesson/Term/Questionは固定IDを持つ。レッスンはたとえ・説明・構成図・ポイント・比較・概念ID・公式出典。問題は分野、単一/複数の正解ID、選択肢別理由、関連概念、出典、任意の模試IDを持つ。問題の正解判定は選択肢集合の完全一致。模試専用問題は通常演習・復習から除外する。

学習履歴はIndexedDBの `saa-learning/state/progress` に単一レコードで保存する。履歴・読了・ブックマーク・途中模試・冒険を1トランザクションで更新。保存失敗は画面で通知する。模試は130分、時刻期限で管理し、画面を閉じた時間も経過時間に含める。再受験開始は現在の試験を置換することを確認する。

## オフラインと更新

配信はHTTPSのGitHub Pages、相対パスでサブディレクトリに対応。無料プランは公開リポジトリを想定する。公開先リポジトリは `hiroshimu0113-web/SAA`。Pages設定と公開確認は `CHECKPOINT.md` で管理する。ローカルでは `pnpm build` → `pnpm preview` を使用する。

ホーム画面へ追加後、そのアイコンからオンラインで起動して設定の保存を行う。Service Workerはビルドごとのハッシュをキャッシュ名に使い、全ファイルを保存してからインストールを成功させる。キャッシュ内容を検査した後だけ「オフライン準備完了」と表示する。

更新は設定から手動で確認・適用する。新パッケージがすべて保存できるまで待機し、失敗時は旧版を残す。動作中の別タブの旧アセットを壊さないため旧キャッシュを即時削除しない。新規導入後はホーム画面アプリから機内モードで再起動して実機確認する。

ブラウザーによるサイトデータ消去を防ぐ保証はない。persistent storageを要求するが成否に依存せず、JSONバックアップを提供する。形式・型を検証してから履歴を置換し、不正ファイルでは既存データを保持する。破損状態は黙ってリセットせず、読み込みエラーとして通知する。

## 教材品質・完成ゲート

数量・ID・参照・正解数・出典・模試比率を自動検証。別担当のレビューで曖昧な要件、誤答理由、最新仕様との矛盾、実質重複を確認する。未確認項目を「確認済み」としない。出典確認日だけでは全文章の監査済みを意味しない。

初版対象外: アカウント認証、同期、課金、App Store、実AWS環境へのリソース作成。本プロジェクト自体はAWS課金を発生させる構成を必要としない。

## 開発と運用

Node.js 22以降とpnpmを使用。`pnpm install`、`pnpm test`、`pnpm build`。開発時は `pnpm dev`。依存バージョンはlockfileに固定。公開はGitHub Actionsを用い、実際の公開先アカウント操作が必要ならユーザーへ具体的操作を引き継ぐ。
