## GR-001（P2）assessment-007の現状説明を変更禁止条件として扱っている

場所：[src/content/rereview/assessment.ts:405](https://github.com/hiroshimu0113-web/SAA/blob/149cc24a57c557ac1e466b853bc8d88f5d5ea6a9/materials/src/content/rereview/assessment.ts#L405)、同419〜420行。点検表のassessment-007も同じ条件解釈。

問題文は「インターネット出口のないVPC内」のタスクがSecrets Managerを呼び、既定DNS名を維持するための「必要なネットワーク構成」を問う。これは現状の説明とも読める。一方、NAT追加案の誤答解説は「インターネット出口を設けない条件を満たさない」と、新たな出口の追加禁止を前提にしている。

Interface endpointの正答は妥当。ただし、新たなネットワーク構成の追加を認めるなら、Public NATとIGW・適切な経路を整えて公開エンドポイントへ接続する案も既定DNS名とAPI到達性を満たし得る。NATだけを配置すれば通信できるという意味ではない。正答キーの変更を求める指摘ではなく、誤答を除外する制約を明記する指摘である。

**修正案：**「インターネット出口を新設せず、Secrets Managerへの通信をプライベートな経路に限定したい」を問題文に追加する。点検表と設計索引も同期する。

**完了条件：**「現在出口がない」と「今後も出口を設けない」を区別し、NAT案を除外する理由が問題文の明示条件から読めること。

根拠：[Secrets Manager VPC endpoint](https://docs.aws.amazon.com/secretsmanager/latest/userguide/vpc-endpoint-overview.html)は、NAT等を使わない私設接続と、private DNSによる既定DNS名の利用を説明する。[NAT gateway](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html)は、Public NAT・IGW・経路を組み合わせたプライベートサブネットからの外向き接続を説明する。この二つを区別するには通信経路の制約が必要。
