## 1. 今の戦闘にあるもの（2026-11-06、main `d12f98b`）

プレイヤーが1戦闘の中で気にすることを数えた。

| 種類 | 内容 | 数 |
|---|---|---|
| 設備の状態 | 稼働・停止・起動待ち・切替中 | 4 |
| 設備の枠と属性 | 処理枠3／支援枠2の区別、AZ、ホスト、待機、レプリカの同期版、Spot、保留上限、再開割引 | 8 |
| データ | 正常／破損、版番号、保存記録 | 3 |

| 敵の予告 | 脅威4種（AZ停止・Spot中断・データ破損・応答タイムアウト）＋通信攻撃、高負荷、読取りの有無、キャッシュのキーと版 | 8 |
| カード以外の操作 | 再開・撤去・データ復元・再試行 | 4 |

### 1.1 複雑さが面白さを邪魔している点

1. **1枚のカードを読むのに、ほかの仕組みを3つ以上知る必要がある。** 例：リードレプリカは「処理枠」「データの版」「読取りの有無」「同期待ち」を知らないと強さが分からない。
2. **やりたいことの前に条件を満たす作業が多い。** 使用条件が18種類あり、引いた札が使えないことがよくある（上の測定）。
3. **成長が見えにくい（推測）。** デッキを強くしても、保留・割引・予約・印の中に効果が埋もれて、手応えが残りにくいと考えられる。測定の裏づけはない。
4. **後始末の操作が4種類ある。** 再開・撤去・復元・再試行は、どれも「元に戻す」作業で、攻めの選択ではない。
5. **キャラの違いが「戦い方」より「条件の違い」になっている。** 各キャラには役があるが、役は条件を満たしたときの1回きりのごほうびで、毎ターンの遊び方は全キャラとも「設備・データ・仕事を少しずつ扱う」形になっている。

## 3. 推奨案B「1キャラ1仕組み」の骨子

### 3.1 全キャラ共通の基本（5つだけ）

| 基本 | 意味 |
|---|---|
| ダメージ | 敵のHPを減らす |
| 防御 | そのターンに受けるダメージを減らす（ターン終了で消える） |
| ドロー | カードを引く |
| 設備 | 置くと、毎ターン終了時に書かれた効果が出る。戦闘が終わると消える。枠は3つで、処理・支援の区別はなくす |
| 停止 | 敵の妨害で設備が1ターン休む。次のターン開始時に自動で戻る（直す操作は要らない） |

- 共通ルールからなくすもの：データ・版・保存記録、仕事と再試行、処理枠／支援枠の区別、起動待ち・切替中、撤去・復元・再開の操作、高負荷・読取り・キャッシュのキー。
- 敵の予告は「攻撃（数値）」と「設備を1つ止める」の2種類だけ。強敵はHPが多いだけ（今と同じ1.35倍）、ボスも今と同じHP72で、**追加の特殊行動は作らない**。
- カードの使用条件は原則なくす。要るときは「設備があればダメージ+2」のように**使えるが、条件を満たすと強くなる**形にする。
- 0コストのカードは「同じカードは1ターンに1回まで」という今の制限をなくす（加速者の仕組みとぶつかるため）。手札上限10、エネルギー3は今のまま。

### 3.2 キャラごとの固有の仕組み（初期案）

それぞれ1つだけ。6つは**伸ばす方向が重ならない**ように選んだ。今の「役」はこの仕組みに置き換える（役の条件・追加攻撃はなくす）。

| キャラ | 固有の仕組み | 伸びる方向 | AWSの考え方 | 動き |
|---|---|---|---|---|
| 守護者 | **冗長** | 守り | 可用性（予備があるので止まらない） | 防御がターン終了で消えず、半分が次のターンに残る。冗長を持つ設備は停止しない |
| 調律師 | **スケールアウト** | 設備 | スケーリング（需要に合わせて台数を増やす） | 同じ設備を重ねて置ける。重ねた台数だけ効果が増える |
| 加速者 | **キャッシュヒット** | 1ターンの連打 | キャッシュ（2回目からは速く返せる） | 同じターンに使う2枚目以降の攻撃カードは+2ダメージ |
| 指揮者 | **保留**（キュー） | 手札をためる | 疎結合（キューに入れて後で処理） | ターン終了時、手札を最大2枚残せる（カードで枠を増やせる） |
| 構築士 | **テンプレート** | カードの複製 | コード化（同じ構成を何度でも再現） | カード1枚をテンプレートに登録すると、毎ターン開始時にそのコピー（使い切り）が手札に来る |
| 復旧者 | **復元** | HPの立て直し | バックアップと復元（正常な時点に戻す） | ターン開始時のHPを記録する。復元カードで記録した値まで戻す |

- 名前は教材に出てくる語から選んだ（教材本文と `knowledge/game-supplement.json` に「冗長」「スケールアウト」「キャッシュヒット」「保留」「テンプレート」が出てくることを確認）。画面で使う前に、`cardTerms` の公開用語IDとの対応を確かめる。
- 強さの目安：守護者は守りが固いが火力が低い、加速者は火力が高いが守りが薄い、という差は残す。完走率の差で調整する（§5）。
- 構築士の今の役「最小権限」（IAMロール・VPCエンドポイント）は仕組みからは外れる。IAMの考え方は共通カードか教材メモで扱う（§6-3）。

### 3.3 カード30形態の割り振り

| 区分 | 枚数 | 内容 |
|---|---|---|
| 共通 | 6 | EC2〈処理〉・EC2〈配置〉・セキュリティグループ・CloudWatch＋共通2種。全キャラが使う |
| 各キャラの専用 | 4×6＝24 | 1枚は仕組みの入口（最初から持つ）、3枚は仕組みを伸ばすカード（報酬で集める） |

- 今の「支援カード（複数キャラで共有）」はなくし、キャラの色分けと報酬を分かりやすくする。
- どの今のカードをどこへ移すか（30形態の対応表）は、案が決まってから書く。

### 3.4 弱い状態から育つ流れ（引き継ぎなし）

- 冒険の開始時は、共通5枚＋仕組みの入口1枚。最初は仕組みがわずかしか動かない。
- 報酬・交換所・休憩所で、仕組みを伸ばすカードを選んで育てる。強敵報酬は今と同じく、所持デッキの構成に合うカードを優先する。
- 冒険が終われば全部リセット。次に別のキャラを選んでも、ずれは起きない。

### 3.5 1ターンの例（加速者）

1. ターン開始。エネルギー3、手札5枚（EC2〈処理〉×2、CloudFront、セキュリティグループ、CloudWatch）。敵の予告「攻撃9」。
2. EC2〈処理〉で6ダメージ → 2枚目のEC2〈処理〉は**キャッシュヒット**で6+2＝8ダメージ → CloudFrontも8ダメージ。
3. エネルギーが切れて終了。受けるのは9ダメージ。設備はないので、停止の予告は関係ない。

今の版で同じ手札を読むと、「通信型の攻撃か」「読取りがある回か」「キャッシュのキーと版」を確かめる必要があった。

### 3.6 そのほかの要素

| 要素 | 扱い |
|---|---|
| マップ | 戦闘種別を通常・強敵・ボスの3つにする（設備・データ経路はなくす）。寄り道（休憩・交換所・知識の間）は今のまま |
| レリック4種 | 残す。「開始時に通信防御8」は「開始時に防御8」へ |
| 知識の間（クイズ） | 今のまま。簡素化の対象外 |
| 画面 | 相棒の表示は設備だけにする（データの印はなくす）。シートの再開・撤去・復元ボタンはなくす。×ボタンは左上、iPhone縦画面320〜390pxで確認 |
| 保存 | 新しい保存キー `saa-build-adventure-v2`。今の `saa-build-adventure-v1` は変換も削除もせず残す。途中の冒険がある人には「前の冒険は保存したまま。新しいルールでは新しく始めます」と表示する |
| 独立試作・資料 | `build-lab.html`、`role-combinations.html/json` などは経緯として残し、通常の入口からは使わない |

## 5. 検証の目安

- 手札で使えない札の割合：今5〜15% → **1%未満**
- 6系統の8階層完走率（固定方策・100シード）：最強と最弱の差が**15ポイント以内**
- 1戦闘あたりのカード以外の操作：0回
- 本人の試遊（iPhone）：「ルールがすぐ分かるか」「自分のキャラを育てている手応えがあるか」を聞く。数値だけで完成と判断しない。
