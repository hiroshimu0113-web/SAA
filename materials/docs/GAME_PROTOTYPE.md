# 設計クエスト：3ミッションの試作

目的：iPhoneで5〜10分遊び、構成を選んだ理由を振り返れるたたき台。全体計画の本格ゲームG1〜G5とは別の試作です。

## 遊び方

1. 学習アプリのホームで「設計クエストを遊ぶ」を選ぶ。
2. ミッションの条件を読み、必要なカードをタップ。同じカードを再タップすると外せる。
3. 「この構成をテストする」で判定と理由を読む。
4. 不足があれば「カードを選び直す」。クリアしたら次へ進む。
5. 3つクリアで結果と関連テキストを表示。途中で閉じても同じブラウザーで再開できる。

1回目でクリアすると3つ星、2回目は2つ星、3回目以降は1つ星。やり直し回数に上限はありません。「最初からやり直す」は確認後にゲーム記録のみをリセットします。学習履歴は残します。

| ミッション | 条件を満たす構成 | 振り返ること |
|---|---|---|
| 1：消えない成果 | EC2 × 1、非公開S3、IAMロール | 計算と永続保存を分け、固定キーを避ける |
| 2：AZ障害 | 別AZのEC2 × 2、ALB、非公開S3、IAMロール | AZ分散・正常先への振り分け・状態の外部化 |
| 3：従業員アクセス | 非公開S3、IAMロール、フェデレーション + MFA | 認証の強化と権限の制限を両立する |

カードは8種類。設計ポイントの上限は順に5、9、4。ポイントは実料金・性能とは関係ないゲーム用の数値です。ルート認証情報の共有とコード内の固定キーは全ミッションで不適合です。

## 保存・オフライン

ゲーム状態は既存のIndexedDB学習記録の `game` に保存し、JSONバックアップに含めます。ゲーム状態には版、現在のミッション、選択カード、試行回数、判定済み状態、獲得星を持ちます。未知形式は読み込まず、新規開始を案内します。

初回オンライン時に「設定」で教材を保存してください。Service Workerがゲームも含むビルド成果物を保存します。ブラウザーのサイトデータを消すと記録が失われます。

## 教材上の前提と限界

- EC2は同じ処理ができるものとして、ネットワーク・OS・アプリ設定の詳細は省略しています。
- ミッション2はステートレスなHTTPサービス、複数AZのALB、ヘルスチェック、S3 Standardを想定します。進行中リクエストの無停止やリージョン全体の障害耐性は保証しません。
- ロールは信頼関係と必要な権限が設定済み、従業員認証はフェデレーション側でMFAを要求する前提です。
- 先行教材の概念を基礎に、2026-10-05にIAMベストプラクティス、EC2ロール、ALB概要、S3ストレージクラスのAWS公式資料を無料で閲覧し、今回の構成と説明を照合しました。全SAA範囲の監査済み教材とは扱いません。
- カードの数値・配置は抽象化です。AWSへ実リソースを作成せず、課金も行いません。

## 次の改善

実機フィードバックを受けて文字量・カード選択・結果のわかりやすさを調整。新しい問題を増やす前に公式出典を再照合し、別の構成も成立するケース、予算の難度、追加ミッションを検討します。

## 公式資料の照合記録（2026-10-05 JST）

- [EC2とIAMロール](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2.html)：長期キーを配布せず一時認証情報で写真バケットへアクセスする例を確認。
- [ALBの概要](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html)：複数AZのターゲットと正常先への振り分けを確認。
- [IAMベストプラクティス](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html)：人のフェデレーション、ワークロードのロール、MFA、最小権限を確認。
- [S3ストレージクラス](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage-class-intro.html)：複数AZのクラスと単一AZのクラスを区別。ゲームではStandardを明示。

有料記事・有料API・課金を伴う情報取得は利用していません。
