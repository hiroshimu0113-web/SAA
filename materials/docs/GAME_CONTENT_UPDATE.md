# 教材からカード・クイズを更新する

ゲーム画面の「教材からカード・クイズを更新」で、GitHub Pagesに公開済みの最新版を取得する。進行中の冒険はそのまま続けられ、新版は次の冒険から使う。通信失敗・不正データ・保存容量不足では以前のデータを保持する。更新済み教材は端末に保存され、オフラインで新しい冒険にも使える。

初回の入口：[クラウドの尖塔・教材更新版](https://hiroshimu0113-web.github.io/SAA/tower/learning.html)。古いページがオフライン保存されている端末は、まずこの入口をオンラインで開く。その後の教材更新には同じ画面のボタンを使う。

## 自動でつながる流れ

1. 教材担当が正本を編集し、確認した教材を `src/content/index.ts` の公開対象にする。
2. テスト・ビルドで `game:export` が実行され、公開済み用語をカード、公開済みの単一選択問題をクイズへ変換する。
3. mainのGitHub Actionsがゲームと `tower/learning-catalog.json` を公開する。
4. 利用者がゲームの更新ボタンを押す。進行中の冒険を終了した後、新しい冒険に新版を適用する。

**ボタンは未公開のGit原稿や任意のPDF/HTMLをAIで解釈するものではない。** 教材の公開まで終われば、利用者がこのチャットへ毎回更新依頼する必要はない。有料APIや実行時のAI呼び出しはない。

## 入力と対象外

| 入力 | ゲームへの反映 |
|---|---|
| `src/content/index.ts` の `terms` | 安定した `study-用語ID` で学習カードを追加・改訂 |
| 同じ公開モジュールの `questions` | 単一選択問題を `study-問題ID` で追加・改訂。設問・全選択肢・正解・解説を保持 |
| `knowledge/game-supplement.json` | 独立公開したリージョン/AZ教材等の構造化された補足。用語・クイズ・既存カードの説明・スターター名 |
| part1/part2の未公開原稿、draftのunits | 自動取り込み対象外 |
| 複数回答問題・模試 | 現行の1回答クイズと形式が異なるため保留。今回q020の1問。件数を生成情報に記録 |
| 任意の公開HTML | 直接解析しない。教材担当が確認した補足を上記JSONへ登録する |

用語の出典は、対応する公開設問またはレッスンの出典を引き継ぐ。教材担当は定義と出典が対応することも確認する。分類台帳は `knowledge/game-classifications.json`。ゲームへの取り込みは内容の独立監査や学習者の習得を意味しない。

## 今回の内容とルール

- 44種類のカード＝従来20種類＋学習カード24種類。21用語と追加教材のヘルスチェック・ALB・残存容量。
- 26問＝従来4問＋公開教材の単一選択19問＋追加教材のリージョン停止・ALBフェイルオープン・切替先データ利用3問。
- スターター名は「切り分け｜責任共有」「防壁｜最小権限」「観測｜ヘルスチェック」。枚数・費用・攻撃・防御・強化値等は従来のまま。
- 並列処理・冗長構成・予備容量・負荷分散・迂回の補足を追加教材へ接続。既存の役と数値効果を維持。
- 新規学習カードは共通で1コスト・5ブロック・1ドロー、強化でブロック＋3。「復習して備える」ゲーム上の効果であり、AWSの性質から攻撃値等を推定しない。
- 戦利品/交換所の3択は従来カード2種類と学習カード1種類。学習カードだけで選択肢が埋まらないようにする。
- 名称・説明・出典はゲーム内「使用中のカードと学べる内容を見る」と長押し詳細で確認できる。

## 保存と互換性

新規冒険は利用する教材のスナップショットをゲーム記録に含む。更新が来ても、デッキ・回答途中のクイズ・解答・報酬・冒険内の説明を途中で変更しない。バックアップにも含み、別端末の教材より古くても再開できる。旧v1〜v4の記録は従来カードと従来クイズで継続する。現在のゲーム保存形式はv4を維持し、教材フィールドを任意追加する。

教材パックはschema 1。スターター性能の上書き・不正なURL・未対応の効果・不正解答を拒否する。同じURLの古いオフラインキャッシュを取得しないよう、更新時はクエリ付きリクエストとno-storeを使用する。最新データの端末保存が成功するまで、使用予定の教材は切り替えない。ゲーム本体が新しくなったときは同梱教材を優先し、古い端末キャッシュへの巻き戻りを避ける。

## 制作者の確認手順

materialsで `pnpm test`、`pnpm game:check`、`pnpm knowledge:check`、`pnpm progress:update`、`pnpm progress:check`、`pnpm build`。ゲームの教材JSONは生成物なので直接編集しない。

ブラウザー試験：`CHROME_PATH=/usr/bin/chromium node scripts/catalog-browser-check.mjs`。新しいカード・スターター名・途中クイズの更新・次の冒険への適用・不正JSON・オフライン再開・古いService Worker下の新規取得を確認する。既存操作の回帰試験は `scripts/touch-browser-check.mjs`。

分類IDは `term-game-*` の24件と `case-game-study-*` の22件を新設。既存 `concept-{strike,guard,probe,parallel,redundant,reserve,balance,detour}-metaphor` の8件を更新。再利用・ゲーム接続は実装済み。新分類と追加説明は独立レビュー待ちとして保持し、未確認のレビュー日を捏造しない。
